# Hermes Operating Contract — Portfolio Tracker C+

This repository serves a public dashboard, but its master ledgers remain private on the VPS.

## Authoritative paths

- Project code: `/data/portfolio-tracker`
- Private runtime: `/data/portfolio`
- Writer bridge: `/data/portfolio-tracker/backend/integrations/hermes_bridge.py`
- Derived snapshot: `/data/portfolio/snapshots/portfolio-snapshot.json`
- Docker cron wrapper: `/data/portfolio-tracker/scripts/portfolio_cron.py`

Do not read `/data/.hermes/.env`, `/data/portfolio/secrets/github-token`, or
any other credential file. Only `portfolio_cron.py publish|maintain` may inject
the repository-scoped PAT into the short-lived publisher child. The one-time
`bootstrap-publish` action may do the same only when an operator explicitly
requests the initial publication; it must never be scheduled.

## Non-negotiable rules

1. Never edit, truncate, reorder, replace, or append directly to `paper.jsonl`, `live.jsonl`, or `market.jsonl`.
2. All writes go through `hermes_bridge.py` or `LedgerStore.append()`.
3. Paper trades use `--portfolio paper`; personal trades use `--portfolio live`. Never copy an event from one ledger to the other.
4. Generate the stable `event_id` before the first write and persist it with the source job/import. Every retry must reuse the same ID and identical payload.
5. Same ID + identical payload is a successful no-op. Same ID + different payload is a conflict; stop and alert instead of generating a replacement ID.
6. Use AMEND only for a mutable field supported by the target action, always with a non-empty `--amend-reason`. Prefer VOID on the original economic event to cancel its effect, always with a non-empty `--void-reason`. VOID may also target an AMEND, which voids the underlying economic event; AMEND may never target a correction and VOID may never target another VOID.
7. Do not store calculated P&L as a master fact. FIFO P&L comes from replay and the derived snapshot.
8. Never commit master ledgers, state files, account identifiers, broker statements, PATs, tokens, or private notes.
9. Do not force push or overwrite an unknown remote SHA. Publisher manual-edit detection must remain fail-closed.
10. A failed snapshot rebuild does not mean the append failed. Check the command result and ledger event ID before retrying. `rebuild.pending` plus the timer recovers derived state.
11. Live opening is approved as USD `0` at `2021-09-27T00:00:00Z`, but it must
    be created only as the first event in the SHA-verified approved staging
    import. Never create it separately or import only part of the plan.
12. Public snapshot fields include transaction date, symbol, shares, price,
    fee, and note. Never add account numbers, broker references, Telegram user
    data, or inferred private context to a note. Only persist note text the user
    explicitly supplied knowing it will be public.

## Required write sequence

For the one-time Live history import, run `scripts/import_live_staging.py`
with the private plan and source workbook in `--check-only` mode first. Only
an exact `status=valid` result may be repeated with `--apply`. The plan must
remain owner-only and must never be committed or printed.

For the approved SPCX public-listing correction, first sync the exact reviewed
repository commit, then run:

```bash
/usr/local/bin/python3 \
  /data/portfolio-tracker/scripts/repair_spcx_listing.py \
  --root /data/portfolio \
  --check-only
```

Only `status=valid`, `target_events=2`, `pending=19`, and `quote_events=15`
authorize the matching `--apply` invocation. The script must create its own
pre-write ledger backup, append one VOID and replacement BUY for each source
BUY plus the quote backfill as one globally locked batch, rebuild once, and
leave `publish.pending`. Do not inspect or print target trade payloads. Publish
only through `portfolio_cron.py publish`, then run
`portfolio_cron.py doctor-active`. A retry after success must report
`status=current` and `pending=0`.

For the approved CBRS public-listing and SKHY ticker corrections, run:

```bash
/usr/local/bin/python3 \
  /data/portfolio-tracker/scripts/repair_instrument_identities.py \
  --root /data/portfolio \
  --check-only
```

Only `status=valid`, `target_events=6`, `quote_events=3`, `pending=15`,
`duplicates=0`, and `already_corrected=false` authorize `--apply`. The script
must create one ledger backup, append five CBRS replacement/VOID pairs, one
SKHY replacement/VOID pair, and three SKHY quote aliases as one globally
locked batch. Cash, FIFO P&L, trade counts, CBRS closed status, and SKHY
shares/cost must remain unchanged. Publish through `portfolio_cron.py publish`,
run `portfolio_cron.py doctor-active`, then require a retry to return
`status=current` and `pending=0`. If a durable JSONL batch is interrupted,
retry the same command: it must verify existing deterministic payloads and
append only the remaining events.

New intake must use `EQUITY:CBRS`, `EQUITY:SPCX`, and `EQUITY:SKHY` after their
listing/ticker effective dates. `SKHYV` is retired from 2026-07-13. Live option
trades must omit `quote_symbol` and receive quotes keyed by their stable
`OPTION:...` instrument ID; never use the underlying stock quote.

For legacy option events, run
`scripts/repair_legacy_option_identities.py --check-only` first. Only an
explicit operator approval may authorize the matching `--apply`. The migration
must preserve cash, FIFO P&L, trade counts, shares, prices, fees, and contract
multipliers; it may only append deterministic replacement/VOID pairs. A retry
must report `status=current` and create no second backup.

After that migration, generate a fresh split-basis plan with
`scripts/repair_split_adjusted_quotes.py --generate-plan`. Do not edit the plan
or apply it automatically. Report only the split facts and aggregate counters,
then wait for explicit approval. `--check-only` must prove the Live and Market
source digests match before any backup or write. `--apply` may append corrected
Market QUOTE events only; it must not change Paper, Live, `swing_trader.py`, or
cron. Preserve the plan as deployment evidence and require an idempotent retry.

For a trade, call:

```bash
cd /data/portfolio-tracker/backend
/usr/local/bin/python3 integrations/hermes_bridge.py \
  --root /data/portfolio \
  trade \
  --portfolio live \
  --event-id live-SOURCE_IMPORT_ID \
  --occurred-at 2026-07-24T15:30:00Z \
  --action BUY \
  --symbol AAPL \
  --instrument-id EQUITY:AAPL \
  --instrument-type EQUITY \
  --quote-symbol AAPL \
  --shares 10 \
  --price 215.25 \
  --fee 0 \
  --source manual-import \
  --note "source description"
```

Paper bot events follow the same command with `--portfolio paper`,
`--source swing-trader`, plus optional `--reason` and `--strategy`.
If the source records a distinct `created_at`, pass it with `--created-at`
and persist it beside the event ID for every retry.

## Telegram `/trade` intake

Accepted grammar:

```text
/trade BUY|SELL SYMBOL SHARES @ PRICE [fee:AMOUNT] [note:PUBLIC_TEXT]
```

Use the immutable Telegram update ID or another persisted Import ID; never ask
the model to invent a fresh retry ID. Convert the source message timestamp to
UTC `Z` once and reuse it on every retry:

```bash
cd /data/portfolio-tracker/backend
/usr/local/bin/python3 integrations/hermes_bridge.py \
  --root /data/portfolio \
  telegram-trade \
  --portfolio live \
  --event-id live-telegram-TELEGRAM_UPDATE_ID \
  --occurred-at SOURCE_MESSAGE_UTC_Z \
  --text "/trade BUY AAPL 10 @ 180.50 fee:1.50 note:PUBLIC_TEXT"
```

Do not run this command before the approved Live staging import is complete. A parser error, missing
Import ID, or missing source timestamp must be returned to the user without a
write.

## Before reporting success

Verify the JSON command response:

- `status` is `appended`, `duplicate`, or
  `recorded_but_rebuild_pending`; the last value means the immutable ledger
  write succeeded and must not be submitted again under a new event ID;
- returned `event_id` matches the requested stable ID;
- a new append reports `snapshot_revision`;
- if `ledger_repairs` is present, report the quarantined byte count and stop
  any direct-ledger writer that caused it; never hide the recovery alert;
- `read --portfolio paper|live` shows the expected position/cash effect;
- no error mentions oversell, negative cash, immutable field, duplicate conflict, corruption, missing quote, or unknown remote edit.

Do not claim GitHub publication succeeded merely because the ledger append succeeded. Publisher state and the remote snapshot are separate side effects.

Before the one-time Live import, the production acceptance command is:

```bash
/usr/local/bin/python3 \
  /data/portfolio-tracker/scripts/portfolio_cron.py doctor-paper-active
```

It must prove that Paper is initialized, Live is still uninitialized and in
canonical `NO_DATA`, and the snapshot, publication and backup are current.
Do not use the less strict ordinary `doctor` result as production acceptance.

After the approved Live import, use `doctor-active`; it must prove both Paper
and Live are initialized and the snapshot, publication and backup are current.

## Read commands

```bash
cd /data/portfolio-tracker/backend
/usr/local/bin/python3 integrations/hermes_bridge.py \
  --root /data/portfolio \
  read \
  --portfolio live
```

Use the derived output for holdings, FIFO P&L, NAV, return, and risk metrics. Do not independently recalculate these figures in a chat response.

## Error handling

- Validation/business invariant error: do not append; correct the proposed event.
- Duplicate conflict: stop and alert with the event ID, never the full sensitive payload.
- JSONL middle corruption: stop, keep last-good snapshot, and request manual repair.
- Truncated final JSONL record: writer/rebuild automatically fsyncs a full
  backup and quarantines the incomplete bytes before truncation. Report
  `ledger_repairs`; use `repair-tail` only for an explicit operator recovery.
- Quote gap: keep that day's NAV/return unavailable. Never substitute
  cash-only NAV or silently forward-fill a trading day. Once every required
  close is continuously available again, the snapshot starts a new
  `LATEST_COMPLETE_SEGMENT` at `performance_effective_date`; never join returns
  across the gap.
- A Paper after-hours event may extend Paper to the next NYSE session, but must
  never extend Live or the SPY benchmark. Schedule the Paper trader in
  `America/New_York` during the regular session; do not use one fixed UTC close
  time across DST changes.
- On the current Hermes UTC-only scheduler, use `45 19,20 * * 1-5` and route
  both invocations through
  `scripts/run_paper_trader_market_window.py`. Exactly the 15:45 New York
  invocation may run the trader; holidays, official 2026-2028 early closes,
  and the other DST candidate must return `skipped`.
- Repair one verified historical quote with
  `scripts/repair_missing_quote.py`. Run its default check-only mode first;
  `--apply` is allowed only when status is `valid`, pending is `1`, and the
  close was independently verified from the approved provider. Never repair
  the current New York session. Retry the identical command after success and
  require `status=current`, `pending=0`, with no second backup.
- A missing SPY holding quote requires an ordinary `QUOTE`; do not treat an
  existing `BENCHMARK_CLOSE` as the holding quote and do not replace it.
- GitHub timeout/409/rate limit: allow the bounded publisher retry or next timer tick.
- Unknown remote edit, 401, or permission 403: fail closed and request human resolution.
